# 누가 — 앱 제작 문서

> 수업 중 10초 관찰 기록을 피드백과 세특 근거로 바꾸는 웨일 웹앱
> NWEC 26 바이브코딩 공모전 · 분야 2 평가·피드백 혁신 · **해밀고등학교 황대연**
> 버전 v0.9.0 (NWEC 26 제출판) · 작성 2026-10-03 · 개정 2026-10-03 (학생 정보 원칙 적용)

> **고정 원칙**: 학생의 학번(반·번호)과 이름은 교사 기기(브라우저)에만 저장한다. 기록이 들어오면 교사가 기억에 의존해 직접 매칭한다. 기록 분석(AI)에는 학번·이름 없이 내용만 보낸다.

이 문서는 **실제로 만든 앱**을 기준으로 쓴 제작 문서다. 기획서(`누가_NWEC26_기획서.md`)가 "무엇을 왜"를 다룬다면, 이 문서는 "어떻게 만들었고, 어디를 고치면 되는가"를 다룬다. 바이브코딩 도구에 그대로 넣어 이어서 만들 수 있도록 파일·함수 이름과 규칙 값을 그대로 적었다.

## 1. 한눈에 보기

**핵심 구조: 수업 중 10초 기록 → 자리에 앉으면 1분 정리 → 피드백·세특 근거**

```
[나이스 시간표] ─ 수업 시각 ─▶ 자동 시작 (녹음은 켰을 때만)
                                  │
  웨일북 ── 카테고리 + 번호 (10초) ──▶ 기록(정리 대기)
  폰 · 워치 ── 카테고리만 (시각) ──▶ 기록(번호는 정리할 때 교사가 고름)
                                  │
                         수업 끝 ─▶ 녹음 정리 (화자1·화자2…, 학생 추정 없음)
                                  │
       교사가 다시 화면을 쓰기 시작 ─▶ 정리 팝업 (약 1분)
                                  │   ① 내 기록마다 그 시각의 발언이 골라져 있음
                                  │   ② 놓친 발언 추천 → 교사가 번호를 고름
                                  ▼
           반(기록 편중) · 피드백 카드 · 세특 근거 묶음·점검
```

**자판기 원칙**: 교사는 버튼만 누른다. 시간표 확인, 녹음 시작·정리, 쉬는 날 건너뛰기, 폰·워치 기록 합치기, 피드백 문장 준비는 뒤에서 저절로 돈다. 교사가 판단하는 곳은 **"누구였는지 번호 고르기"**와 **"보내기·저장"** 두 군데뿐이다.

## 3. 기술 선택

| 선택 | 이유 |
| --- | --- |
| **HTML 한 파일 + 순수 자바스크립트** (프레임워크·빌드 의존성 없음) | ZIP을 풀고 더블클릭하면 웨일에서 바로 열린다. 인터넷 없이도 데모가 된다. 심사위원 PC 환경을 타지 않는다. |
| 화면 렌더링: 작은 `h()` 함수로 DOM을 직접 만들고 상태가 바뀌면 다시 그림 | 의존성 없이 코드 양을 줄이고, 바이브코딩으로 고치기 쉽다. |
| 저장: `localStorage`(상태 JSON), `IndexedDB`(음성) | 학번·이름이 서버로 가지 않는다. 실제/데모 상태를 다른 키로 분리. |
| 녹음: `MediaRecorder`(webm/opus 24kbps, 10초 조각), `Wake Lock` | 50분 수업 약 9MB. 화면 꺼짐 방지. |
| 자리 감지: 입력·화면 보임·포커스 이벤트 + 선택 `IdleDetector` | 카메라·화면 내용을 보지 않고 "다시 쓰기 시작"만 감지. |
| 기기 연결: Web Crypto `AES-GCM` 종단간 암호화 | 서버(전달함)는 내용을 읽을 수 없다. |
| 서버: **Cloudflare Workers + KV** 한 파일(`worker.js`) | 무료 구간으로 시작 가능, 배포가 단순, 상태가 적다. |
| AI: Gemini API(서버에서만 호출) | 교사는 키를 넣지 않는다. 모델 이름은 환경 변수. |
| 학교 정보: 나이스 교육정보 개방 포털, 공공데이터포털 특일 정보 | 시간표·학사일정·공휴일을 저절로. |
| 글꼴: IBM Plex Sans KR(웹 글꼴), 없으면 맑은 고딕 등 시스템 글꼴 | 오프라인이어도 깨지지 않는다. |

## 4. 폴더 구조와 빌드

```
nuga/
├─ src/                    앱 원본
│   ├─ index.html          틀 (<style>/*__STYLE__*/, <script>/*__SCRIPT__*/ 자리)
│   ├─ style.css           디자인 토큰·레이아웃·컴포넌트 (264줄)
│   ├─ core.js             유틸·상태·시계·시간표·저장·IndexedDB·API·암호화 (246줄)
│   ├─ engine.js           데모 데이터·발언 추천·문장 변환·피드백·세특 점검 (323줄)
│   ├─ ui1.js              틀·상태 줄·데모 바·수업 화면·녹음·자리 감지·정리 팝업·가상 워치 (520줄)
│   └─ ui2.js              정리·반·피드백·세특·설정·처음 설정·학생 화면·기기 연결·시작 (564줄)
├─ tools/
│   ├─ build.py            src → dist/index.html 한 파일로 합침
│   ├─ flow.py · flow2.py · flow3.py · e2e.py · e2e_rec.py · ws.py   브라우저 점검 (11절)
│   ├─ capture.py          안내 PDF용 화면 캡처
│   └─ render_guide.py     안내 PDF 만들기
├─ dist/index.html         제출용 앱 (약 162KB)
├─ video/                  시연 영상: capture_kf.py(데모 조작·캡처) · compose.py(합성) · nuga_demo.mp4/.vtt
├─ server/                 누가 서버 참고 구현 (8절)
└─ guide/                  사용 방법·심사용 안내 PDF 원본(HTML)과 화면
```

**빌드**: `python3 tools/build.py` → `dist/index.html`.
스크립트 순서는 `core.js → engine.js → ui1.js → ui2.js`이고, 마지막 줄 `init();`이 앱을 시작한다. 모든 함수가 전역이라 순서만 지키면 된다. 제출 ZIP의 `source/`에서 다시 빌드한 결과가 제출본과 바이트 단위로 같음을 확인했다.

## 5. 화면 구성

왼쪽 메뉴(폭 720px 이하에서는 아래 탭 막대) 6개와, 메뉴 밖 화면 4개로 이루어진다.

| 화면 | 함수 | 하는 일 |
| --- | --- | --- |
| **수업** | `viewLesson` | 지금 수업(교시·반·단원·성취기준), 눈여겨볼 학생 3명, 카테고리 4칸, 번호 격자, 오늘 기록 6건, 녹음 상태. 수업이 아니면 반 고르기 + [수업 시작](보강·쉬는 날에도 가능). |
| **정리** | `viewReview` | 정리 대기 수업([지금 정리]), 녹음 정리 중·대기, 보완 대기 기록, 추천함(확인 안 한 놓친 발언). |
| **반** | `viewClass` | 학생별 기록 수·카테고리 점, 기록 1건 이하 주황 테두리, 학생 누르면 기록 목록·눈여겨볼 학생 지정. |
| **피드백** | `viewFeedback` | 기간(진행 중 단원·끝난 단원·최근 7일·학기) 고르기, 학생별 카드(잘한 장면·다음 도전·근거), 전체 복사·CSV·학생용 QR 쪽지(학생별 링크 복사), 성취기준별 관찰 근거표. |
| **세특** | `viewDraft` | 왼쪽 근거 기록(성취기준별 묶음, 체크한 것만 사용), 오른쪽 편집기·바이트·[초안 정리]·[프롬프트 복사]·점검 6가지·문장별 근거. |
| **설정** | `viewSettings` | 웨일 스페이스 연동, 학교급·과목·카테고리·번호만 보기·교사 지침, 반·명단, 시간표·종 시간·쉬는 날, 진도·성취기준, 수업 녹음, 자리 정리 팝업, 기기 연결, 누가 서버·AI 처리, 백업, 데모. |
| 처음 설정 | `renderOnboarding` | 첫 화면(데모로 바로 써 보기 / 웨일 스페이스로 로그인 / 직접 시작하기) → 1. 학교급·과목 → 2. 반·명단 → 3. 시간표. |
| 정리 팝업 | `Popup.show` | 7.6절. |
| 학생 화면 | `renderStudent` (`#card=`) | 쪽지 QR을 찍으면 그 카드만 보임. 로그인·저장 없음, 카드에 반·번호·이름 없음. |
| 데모 바·가상 워치 | `renderDemoBar`, `renderWatchSim` | 데모 시계, [수업 끝내고 자리로 ▶], [가상 워치], [한글날(공휴일)로], [처음부터], [데모 끝내기]. |

상단 **상태 한 줄**(`renderStatus`)은 "2교시 2-3반 수업 중 · 녹음 중 · 워치 연결됨 · 정리 대기 1 · 웨일 스페이스" 식으로 뒤에서 도는 일을 보여 준다. 쉬는 날엔 "오늘 쉼 · 한글날".

## 6. 데이터 모델

### 6.1 저장 위치

| 키 | 내용 |
| --- | --- |
| `localStorage['nuga.mode']` | `real` 또는 `demo` |
| `localStorage['nuga.state.real.v1']` | 실제 사용 상태(JSON) |
| `localStorage['nuga.state.demo.v1']` | 데모 상태(JSON). 실제 데이터와 섞이지 않음 |
| `IndexedDB 'nuga' / store 'audio'` | `{ key: 수업키, blob, createdAt, deleteAt }` 음성, 24시간 뒤 삭제 |

저장은 `save()`(120ms 모아서) / `saveNow()`(즉시, 창 닫을 때)로 한다.

### 6.2 상태 `S` (`defaultState`)

```js
{

  settings: {
    level: 'elem'|'middle'|'high', subject, categories: [4개], numberOnly,

    recording: { enabled:false, checklist:false, ttlHours:24, items:{approve,privacy,consent,transfer} },
    popup: { enabled:true, maxSuggestions:3, quietMin:2, presence:false, notify:false },

  },
  account: { provider:'none'|'whalespace'|'whalespace-demo', userType, sid, token, exp },
  school: { name, code, office, kind, source:'manual'|'neis'|'whalespace'|'demo' } | null,
  classes: [{ id:'2-3', students:[{ no, name }] }],
  timetable: [{ weekday, period, class }],          // 주간 격자
  timetableDated: [{ date, period, class }],        // 나이스에서 가져온 날짜별 시간표 (우선)
  extraLessons: [{ key, date, class, period:'수동', start, end }],  // [수업 시작]
  skipLessons: [수업키], skipDays: [{ date, reason }],
  progress: [{ class:'*', from, to, unit, standards:[코드] }], standards: { 코드: 설명 },
  records: [기록], lessons: { 수업키: 수업 상태 }, transcripts: { 수업키: 전사 }, suggestions: [추천],
  feedbackSent: { 'cls_no_periodId': { at, period } },  // 쪽지를 만든 기록 (이 기기에만)
  feedbackEdits: {},
  drafts: { 'cls_no': { text, savedAt } }, watchExtra: { cls: [번호] },
  sync: { role:null|'main'|'satellite', key, channel, devices, outbox:[기록 id] },
  demoClock: null | ms, demoSetAt: null | ms
}
```

### 6.3 주요 객체

- **수업키**: `YYYY-MM-DD_반_교시` (예: `2026-10-13_2-3_2`, 직접 시작은 `2026-10-03_2-3_수동1740`).
- **기록(record)**: `{ id, class, no(폰·워치 기록은 교사가 고르기 전까지 null), cat(0~3), time(ISO), lessonKey, unit, std:[코드], note, noteSource:'typed'|'transcript', source:'direct'|'suggestion', device:'whalebook'|'phone'|'watch', status:'pending'|'confirmed'|'skipped', transcriptRef }`
- **수업 상태(lessons[key])**: `{ started, startedAt, ended, endedAt, processing, aiPending, retryAt, popupDone, snoozeUntil, notified, noticed, skipRecording, recordingDemo }`
- **전사(transcript)**: `{ id, lessonKey, source:'ai'|'demo', segments:[{ id:'s1', t0:'10:02:41', speaker:'화자4', text, sum }] }`
- **추천(suggestion)**: `{ id, lessonKey, segId, t0, speaker, text, sum, criteria, cat, score, status:'new'|'recorded'|'dismissed'|'later', recordId }`

> 주의: 기록 날짜는 `recDay(r)`(기기 시간대 날짜)로 비교한다. ISO 문자열 앞 10자는 UTC라 한국 시간 오전 9시 전 기록이 전날로 잡힌다(제작 중 발견해 고친 버그).

## 7. 핵심 로직

### 7.1 시간표와 수업 판단 (`core.js`)

- `periodTimes(bell)`: 1교시 시작·수업 길이·쉬는 시간·점심(몇 교시 뒤, 길이)으로 교시별 시작·끝 분을 계산.
- `skipReason(날짜)`: **직접 추가한 쉬는 날 → 2026 공휴일 목록 → 주말** 순으로 이유를 돌려준다(개천절이 토요일이어도 "개천절"로 보임).
- `lessonsOn(날짜)`: 쉬는 날이면 시간표 수업은 없고 **직접 시작한 수업만** 남긴다. 아니면 `timetableDated`(나이스) → 없으면 주간 `timetable`. `skipLessons`(이번 시간 아님)는 뺀다.
- `currentLesson(t)`, `nextLesson(t)`, `lessonByKey(key)`, `progressAt(반, 날짜)`.

### 7.2 5초 주기 `tick()` (`ui1.js`)

1. 지금 수업이 있고 시작 전이면 `started` 표시 → `onLessonStart` (녹음 조건이 맞으면 `Recorder.start`).
2. 다음 수업 1분 전(실사용·녹음 켬): "곧 녹음을 시작합니다" 알림 + [이번엔 쉬기].
3. 끝난 수업은 `ended` 표시 → `onLessonEnd` (녹음 멈춤 → `processAudio`).
4. **녹음 정리 재시도**: `aiPending`인 수업은 2분마다 IndexedDB에서 음성을 꺼내 다시 보낸다.
5. 데모 시계·상태 줄 갱신, `Popup.check('tick')`.

그 밖에 20초마다 `syncLoop`(기기 연결), 시작할 때 `cleanupAudio`(기한 지난 음성 삭제).

### 7.3 녹음 (`Recorder`)

- 조건: 설정의 **확인 4가지(학교장 승인·개인정보 검토·안내와 동의·외부 처리 검토)를 모두 체크** → [시간표 수업 시각에 저절로 녹음] 켬.
- `getUserMedia({ audio: { channelCount:1, echoCancellation, noiseSuppression } })`, `audio/webm;codecs=opus` 24kbps, 10초마다 조각.
- 멈추면 IndexedDB에 `deleteAt = 지금 + 24시간`으로 저장.

### 7.4 녹음 정리 (`processAudio`)

1. 서버가 없으면 `aiPending` 표시 후 "서버를 연결하면 정리됩니다".
2. `POST /ai/transcribe`(음성) → 구간 `{ start(초), speaker, text, summary }` → 수업 시작 시각에 더해 `t0` 계산 → `transcripts[key]`.
3. `POST /ai/suggest` → 추천. 실패하거나 비면 **규칙 엔진**(`ensureSuggestions`)으로 대신.
4. 정리 팝업이 이미 떠 있으면 `Popup.refreshIf(key)`로 바로 채운다.

### 7.5 발언 후보와 놓친 발언 추천 (`engine.js`)

- **교사 화자**: 글자 수가 가장 많은 화자(`teacherSpeaker`).
- **내 기록의 후보 발언** (`candidatesFor`): 교사가 아닌 화자의 구간 중 **기록 시각 −60초 ~ +15초**. 카테고리와 맞으면 +2(질문=의문형, 협동=같이·역할·도와, 발표=평서문, 탐구=그래프·결과·실험·연결), 시간 차 1분당 −1. 가장 높은 것을 미리 골라 둔다.
- **놓친 발언** (`buildSuggestions`): 교사 화자와 이미 기록에 쓰인 구간을 빼고, 아래 기준으로 점수를 매겨 상위 10개.

| 기준 | 카테고리 | 단서(정규식 요지) | 가중치 |
| --- | --- | --- | --- |
| 깊이 있는 질문 | 질문 | 왜·그럼·만약·어떻게·바뀌 + 의문형 | 3 |
| 개념 연결 | 탐구 | 배운·지난·비슷·처럼·같은 원리 | 3 |
| 오개념 수정·자기 성찰 | 탐구 | 다시 보니·틀렸·잘못·반대로·수정 | 3 |
| 근거 제시 | 탐구 | 그래프·결과·실험·데이터·보면 (평서문) | 2.5 |
| 다른 의견 확장 | 발표 | 덧붙·이어서·말한 거 | 2.5 |
| 협력·배려 | 협동 | 같이·정리해 줄·도와·역할·할게 | 2 |

  점수 = 가중치 + 길이(최대 60자, 0~1) + 단원 낱말 0.6. "네·화장실·몇 쪽" 같은 말과 12자 미만은 0점.
- 서버 AI가 있으면 같은 기준을 프롬프트로 주고 결과를 쓴다. **학생이 누구인지는 어느 경로에서도 추정하지 않는다.**

### 7.6 자리 정리 팝업 (`Popup`)

**뜨는 조건** (`Popup.check`): 팝업 켬 · 이미 떠 있지 않음 · 학생 화면 아님 · 지금 수업 중 아님 · 다음 수업까지 `quietMin`(2분) 이상 · 오늘 끝났고 정리 안 한 수업에 내 기록이나 추천이 있음 · **자리 신호**(입력·화면 다시 보임·포커스·IdleDetector, 또는 45초 안에 입력). 창이 숨겨져 있으면 운영체제 알림("3교시 2-3반 정리 · 1분")을 대신 보낸다(허용 시).

**구성**: 머리(교시·반·단원·시간·녹음 상태·"정리 약 1분"·진행 막대) → ① 내 기록(기록마다 미리 고른 발언, 폰·워치 기록은 번호 고르기, 한 줄 보완 입력, [다른 후보], 표현 칩, [건너뛰기], **[N건 한 번에 저장]**) → ② 놓친 발언(최대 3개 + [더 보기], **[누구였는지 번호 고르기]**·[아니요]·[다시 듣기]) → [나중에](다음 빈 시간에 다시) / **[끝]**(남은 추천은 추천함으로, 기록 부족 학생 수 안내).

**늦게 끝난 정리 처리**: 팝업이 먼저 뜨고 녹음 정리가 나중에 끝나면, 추천을 이어 붙이고 비어 있던 후보도 채운다(교사가 직접 쓴 문구는 건드리지 않음). 정리 중에는 "녹음을 정리하는 중이에요"를 보여 준다.

### 7.7 자리 감지 (`Presence`)

`pointerdown·keydown·touchstart·wheel`, 4초 간격 `pointermove`, `visibilitychange`(다시 보임), `focus`. 설정에서 [자리 감지 켜기]를 누르면 `IdleDetector`(화면 잠금 해제)도 쓴다. 카메라·화면 내용은 쓰지 않는다.

### 7.8 눈여겨볼 학생 (`watchListFor`)

최근 7일 기록이 가장 적은 3명. 동점이면 전체 기록 수, 번호 순. 교사가 반 화면에서 지정한 학생(`watchExtra`)이 먼저.

### 7.9 피드백 카드 (`feedbackFor`)

- 기간 안에서 내용이 있는 기록을 최근 순으로 보고, **카테고리가 다른 2건**을 고른 뒤 시간 순으로 보여 준다.
- 문장 변환 `toStudentSentence`: "~함" → "~한 점이 좋았어요.", "~찾음" → "찾아낸 점이…", "~도움" → "도운 점이…", 동작 명사 → "~한 점이…".
- 다음 도전: 그 학생에게 **가장 적은 카테고리**에 맞는 학교급별 문장(`NEXT_CHALLENGE`).
- 근거가 없는 학생은 빈 칭찬 대신 "다음 수업 관찰 대상에 올리기".
- 성취기준별 관찰 근거표(`stdMatrix`): 학생 × 성취기준 기록 수, 0칸 강조.

### 7.10 세특 근거 묶음과 점검

- **[초안 정리]** (`draftFromRecords`): 체크한 기록을 성취기준별로 묶어 `toRecordSentence`(명사형: 이미 ㅁ 받침이면 그대로, 동작 명사면 "~함.", 아니면 "~을 보임.")로 바꾼다. **같거나 비슷한 문장(글자 2-gram 자카드 ≥ 0.75)은 하나로 합치고 근거만 더하며**, 바이트 한도를 넘는 문장은 넣지 않는다. 서버 AI가 있으면 `/ai/draft` 결과를 쓰고, 비면 규칙으로 돌아간다.
- **나이스 바이트** (`neisBytes`): 한글 등 3B, ASCII 1B, 줄바꿈 2B. 목표 구간 96~100%.
- **점검 6가지** (`checkDraft`): ① 바이트 한도 ② 명사형 종결(마지막 글자 받침이 ㅁ, 유니코드 종성 16) ③ 금지어(대회·수상·자격증·어학시험·사교육·부모·교외 등 기본 사전) ④ 학생 이름 ⑤ 근거 연결(문장–기록 2-gram 자카드 ≥ 0.18) ⑥ 같은 반 다른 학생과 비슷한 문장(3-gram 자카드 > 0.6).
- **[프롬프트 복사]** (`promptFor`): 다른 AI에 붙여 쓸 수 있는 규칙 포함 요청문.

### 7.11 기기 연결과 암호화 전달함

- 본체 [폰 연결하기] (`pairMain`): 32바이트 열쇠 생성 → `channel = SHA-256(열쇠) 앞 16바이트(hex)` → 연결 코드 `{ k:열쇠, s:서버 주소, tt:시간표, b:종 시간, cats, lv }`를 b64url로 (반 인원·명단 없음). https에서는 `#pair=코드` 링크와 QR(qrcodejs, 필요할 때만 불러옴), 파일로 열면 코드 복사.
- 보조 기기 (`acceptPair`): 역할 `satellite`, 명단 없음. 화면은 카테고리 4칸뿐(`viewSatellite`, 메뉴는 수업·설정). 누르면 기록이 `outbox`에 쌓인다.
- `syncLoop`(20초): 보조 기기는 **`outgoingRecord()` = `{ id, cat, time, device }`만** `AES-GCM`(12바이트 IV)으로 봉해 `POST /box/{channel}`. 반·번호·이름·메모는 보내지 않는다.
- 본체는 `GET`으로 받아 풀고 `ack`(서버에서 삭제). `incomingRecord()`가 **기록 시각으로 본체의 수업(반)을 찾아 붙이고 번호는 비워 둔다**(직접 시작한 수업 포함, 수업 밖이면 반도 비움).
- 번호는 교사가 기억에 의존해 고른다: 정리 팝업의 내 기록 카드에 "폰(워치)에서 온 기록이에요. 누구였는지 번호를 골라 주세요" + 번호 격자. 그 시각의 발언 후보가 함께 보여 기억을 돕는다. 번호를 고르지 않은 기록은 저장하지 않고 정리 → 보완 대기에 남는다(반·번호 고르기).

### 7.12 웨일 스페이스 로그인 흐름

1. [웨일 스페이스로 로그인] → `서버/auth/whalespace?return=앱주소`. **교사만** 로그인한다(학생 로그인 없음).
2. 서버가 OAuth → userinfo → 서명 토큰 발급 → `앱주소#ws=<b64url JSON>`으로 돌려보냄.
3. `handleHash`: 교사 `{ userType:'tea', sid(해시), token, school{name, code, office, kind} }` → 학교가 바로 잡힘. 오류 `{ error }`는 안내 문구로(취소·반 번호 없음·학생이 교사 화면 등).
4. 이후 API 요청에 `Authorization: Bearer 토큰`. 서버는 사용자 이름·반·번호를 읽지 않고, 학생 계정은 `wrong_role`로 돌려보낸다.
5. 서버가 없으면(승인 전) 안내 창에서 **데모 로그인으로 흐름 보기**.

## 10. 개인정보·안전 설계

- **학번·이름은 교사 브라우저에만.** 서버·AI 어디에도 학번·이름을 보내지 않는다.
  - 폰·워치 기록(전달함)은 교사 기기끼리 주고받는 종단간 암호문이라 서버는 반·번호를 읽을 수 없고, 받으면 바로 지운다.
  - 피드백은 학생용 QR 쪽지로만 건넨다. 카드 내용은 QR 주소의 # 뒤에만 있어 서버에 가지 않고, 반·번호·이름을 넣지 않는다. 누구 쪽지인지는 교사가 손으로 건네는 종이에만 적힌다.
  - AI 로 가는 글(세특 기록 문장, 추천용 전사, 복사용 프롬프트)은 내용만 보내고, 명단 이름(성을 뺀 이름 포함)을 `scrubNames()`로 ○○ 처리한다.
  - 웨일 스페이스는 교사만 로그인한다. 서버는 이름·반·번호를 읽지 않는다.
  - 녹음을 켜면 음성 자체는 Gemini 로 가므로, 수업 중 불린 이름이 들릴 수 있다. 이 때문에 녹음은 확인 4가지 뒤에만 켜진다.
- 데모는 번호만 쓰는 **합성 데이터**이고 화면에 "합성 데이터 · 실제 학생 정보 없음"을 늘 표시.
- 녹음은 기본 꺼짐, 확인 4가지 전에는 켤 수 없음. 음성은 기기 24시간, 서버는 저장하지 않음. 화면에 "법률 자문이 아니며 학교·교육청 확인이 필요" 표기.
- AI는 화자 구분과 후보 고르기까지만. 누구인지, 잘했는지는 교사가 정한다.
- 세특은 체크한 기록만 근거로, 최종 작성·나이스 입력은 교사. 백업 파일에는 AI 키·연결 열쇠를 넣지 않는다.
- 효과 수치는 실측 전이라 어디에도 넣지 않았다. 성취기준은 "[예시]" 표기.

## 12. 제작 과정 기록 (바이브코딩)

**만든 순서**: 디자인 토큰·컴포넌트(`style.css`) → 상태·시간표·저장·암호화(`core.js`) → 데모 데이터·추천·문장·점검 엔진(`engine.js`) → 수업·녹음·정리 팝업(`ui1.js`) → 나머지 화면·설정·연결(`ui2.js`) → 빌드 → 브라우저 자동 점검 → 서버 → 서버 점검 → 화면 캡처 → 안내 PDF → ZIP → 시연 영상.

### 12.1 시연 영상 만들기

- 길이 13.6초, 1920×1080, 30fps. 데모에서 시계를 10:34:22로 옮기고 가상 워치로 [질문] → 3번 → 저장 → 웨일북 도착 → [수업 끝내고 자리로 ▶] → 정리 팝업 → 3번 기록에 10:34:18 발언("근데 촉매를 넣으면 평형 위치도 바뀌나요?")이 골라져 있음 → [4건 한 번에 저장] → [끝].
- `video/capture_kf.py`: Playwright로 1600×900(배율 2.4, 3840×2160) 화면을 장면마다 찍고 버튼 위치를 `meta.json`에 남긴다.
- `video/compose.py`: 키프레임 사이 전환, 카메라 확대·이동(워치·오늘 기록·팝업), 탭 표시, 강조 테두리, 아래 띠 자막("데모 화면 · 합성 데이터" 상시 표시), 마무리 화면 → ffmpeg(libx264, CRF 18).
- 영상 속 발언 짝짓기는 실제 앱 규칙(7.5절 −60초 ~ +15초, 질문은 의문형)이 고른 결과다.

**점검하며 찾아 고친 문제**

| 문제 | 원인 | 고친 방법 |
| --- | --- | --- |
| 정리 팝업에 놓친 발언이 0개 | 녹음 정리가 끝나기 전에 팝업이 먼저 떠 빈 목록을 붙잡음 | 그리기 때마다 추천을 이어 붙이고, 정리 중 문구 표시, 데모는 전환 중 팝업 보류 |
| 팝업의 내 기록이 "후보 없음"인데 "다른 후보 (2)" | 후보가 늦게 생겨도 처음 선택(-1)이 그대로 | 후보가 생기면 첫 후보로 채움(직접 쓴 문구는 유지) |
| 오전 9시 전 기록이 오늘 기록에서 빠짐 | ISO 날짜(UTC) 비교 | `recDay()`로 기기 시간대 날짜 비교 |
| 공휴일·주말에 [수업 시작]이 안 됨 | 쉬는 날이면 수업 목록 전체를 비움 | 시간표 수업만 빼고 직접 시작한 수업은 남김 |
| 개천절(토)이 "주말"로 보임 | 쉬는 날 이유 순서 | 직접 추가 → 공휴일 → 주말 순 |
| 세특 초안에 같은 문장 반복 | 비슷한 관찰 기록을 그대로 나열 | 자카드 0.75 이상 합치기 + 바이트 한도 |
| 데모 반의 절반 이상이 "기록 부족" | 데모 기록 밀도가 낮음 | 수업당 5~8건, 가중치 조정(부족 7명) |
| 서버 AI 초안이 비면 편집기가 빈칸 | 빈 배열을 성공으로 처리 | 비면 규칙 정리로 대체 |
| 직접 시작한 수업이 "수동교시"로 표시 | 교시 이름 조합 | `perLabel()`로 "수업" 표시 |
| 녹음 정리 실패 뒤 다시 시도 안 됨 | 재시도 없음 | 2분마다 자동 재시도, 팝업에 "정리 대기" |
| 폰 기록이 본체 수업에 안 붙음 | 보조 기기는 본체의 직접 시작 수업을 모름 | 본체가 기록 시각으로 수업을 찾아 붙임 |
| 서버 로그인 돌려보내기에서 오류 | `Response.redirect()`는 헤더를 못 바꿈 | 302 응답을 직접 만듦 |
| ZIP 안 한글 파일 이름이 깨질 수 있음 | UTF-8 표시 비트 없음 | 표시 비트를 켜서 다시 압축 |
| 정리 팝업 위에 가상 워치가 겹쳐 보임 | 팝업(z-index 60)보다 워치(70)가 위 | 팝업을 75로 올림(알림 80은 그대로 맨 위) |

## 14. 이어서 만들 때 AI에게 주는 규칙

바이브코딩 도구에 이 문서와 `source/`를 함께 주고, 아래 규칙을 붙인다.

```
너는 '누가' 웨일 웹앱을 이어서 만드는 개발자다. 이 문서(앱 제작 문서)와 source/ 코드를 기준으로 한다.
지켜야 할 것:
1. 앱은 HTML 한 파일로 빌드된다(tools/build.py). 프레임워크·외부 의존성을 추가하지 않는다. 오프라인에서 데모가 동작해야 한다.
2. 교사는 버튼만 누른다(자판기 원칙). 설정을 늘리기보다 기본값과 자동 처리를 늘린다.
3. AI는 학생이 누구인지 추정하지 않는다. 화자는 '화자1·화자2'로만, 판단(번호 고르기·보내기)은 교사가 한다.
4. 학번·이름은 브라우저 밖으로 보내지 않는다. AI 에는 내용만 보내고 scrubNames()로 이름을 지운다. 기기 간 기록은 종단간 암호화한다. 학생 로그인·학생 정보 서버 저장을 만들지 않는다.
5. 녹음은 기본 꺼짐, 확인 4가지 전에는 켜지지 않는다. 음성은 기기 24시간, 서버 저장 없음.
6. 데모 데이터는 번호만 쓰는 합성 데이터다. 실제 학생 정보, 실측하지 않은 효과 수치, 가짜 후기를 넣지 않는다.
7. 날짜 비교는 recDay()/ymd()로 기기 시간대 기준으로 한다.
8. 고친 뒤에는 tools/flow.py(1280·420·390), flow2.py, flow3.py, server의 npm test를 돌려 pageerror 0건을 확인한다.
9. 화면 문구는 쉬운 우리말로, 버튼 이름은 안내 PDF·README와 같게 유지한다.
```
