# 누가 구동안내서 (초안)

> 2026 공공 AI 대전환 챌린지 세션1 제출용 초안입니다. 11.6 제출 전에 화면 캡처와 실측 수치(모델 비교표)를 넣어 완성합니다.
> 모든 시연 데이터는 합성 데이터입니다. 실제 학생 정보와 실제 수업 음성은 쓰지 않습니다.

## 1. 한 줄 소개

**누가**는 수업 중 10초 기록, 수업 후 30초 보완, 수업 녹음 기반 추천을 거쳐 학기 말 학교생활기록부 초안을 만들고, 그 초안이 기록과 교사 지침을 얼마나 지켰는지 보여 주는 교사용 앱입니다.

## 2. 구성 요소

| 구성 | 하는 일 | 설치 |
| --- | --- | --- |
| PC 앱 (Windows) | 명단·시간표·진도, 오늘·누가기록·초안·검토, AI 제공자, 녹음 설정 | `Nuga_<버전>_x64-setup.exe` |
| 웹 데모 | PC 앱과 같은 화면 (브라우저 저장소) | https://dacisosl.github.io/NUGA/ |
| 폰 앱 (Android 8 이상) | 위젯·알림 1차 기록, 수업 녹음, 동기화 | `mobile-debug.apk` |
| 워치 앱 (Wear OS, 선택) | 손목에서 [기록] → 번호 | `wear-debug.apk` |
| 릴레이 서버 | 종단간 암호문만 24시간 중계 | `npm run relay` 또는 Docker |

설치 파일은 GitHub Releases 에 있습니다. PC 설치 파일에는 로컬 LLM 실행기(llama.cpp CPU 빌드)가 들어 있고, 모델(GGUF)은 처음 쓸 때 내려받습니다.

## 3. 심사용 빠른 시연 (API 키 없이 10분)

1. PC 앱(또는 웹 데모)을 처음 열고 **데모 모드로 둘러보기**를 누릅니다.
   - 합성 학급 2개(25·26명), 한 학기 합성 기록, PDF기록, 예시 성취기준, 합성 모의 수업 스크립트(화학 평형, 10분)가 들어갑니다.
2. **현황판**(메인 화면 하나): 위는 **기록 계단**, 아래는 **학생 카드**.
   - 기록 계단은 [접기 · 간략히 · 자세히]. 간략히(기본)는 칸마다 학생 수만큼 점(하늘빛 = 이번 주 기록)이고, **출발선(0건) 학생만은 이름표**로 모두 보입니다 — 누르면 그 학생 기록. 자세히는 출발선(0건)부터 2건 이하 · 3건 이상 · 5건 이상 … 으로 오르는 이름표 계단입니다.
   - 학생 카드: 이름 → 번호 → 최근 기록, 맨 아래 **기록 흐름 그래프**(3월부터 오늘까지 — 기록이 있는 날 오르고 없는 날 천천히 내려옵니다. 가장 높을 때·낮을 때에 붉은 점). 기록이 부족한 학생은 카드가 옅은 붉은빛입니다.
   - 카드를 누르면 학생 기록 창이 열리고, **맨 위 입력칸에 적고 Enter** 하면 바로 기록됩니다(분류·날짜는 고르지 않아도 됩니다).
   - 설정 → 화면 → **학생 카드**에서 '강한 구분'을 고르면 수집 카드처럼 빛깔 테두리가 생깁니다. 빛깔은 회색 → 초록 → 파랑 → 보라 → 금색(적음 → 많음)이고, 카드 위 **[기록 수 | 도달 정도]**로 기준을 바꿉니다.
3. 상단 바의 **일괄 기록 +**: 관찰기록 여러 건을 한 번에 넣습니다.
   - 붙여넣기(엑셀 칸 · 한글 문서 · 메모) 또는 **PDF·사진에서 글자 읽기**(스캔본은 OCR, PC 안에서만). 한 줄 = 기록 하나, 줄 앞의 번호·이름·날짜(9/18)·분류([발표])를 함께 읽습니다.
   - 다음 단계 표에서 줄마다 학생·날짜·분류·내용을 확인하고 [기록 N건 추가]. 번호와 이름이 다르거나 스캔 글의 이름이 한 글자 틀리면 '확인 필요'로 표시됩니다.
4. 상단 바의 **미반영 N** → **쉬는 시간 기록** 팝업
   - 왼쪽 자동 추천: 추천 문구 한 줄과 명단만 보입니다. 명단에서 학생을 누르면 바로 기록됩니다. 발언 원문·앞뒤 문맥·판단 기준은 [자세히]로 펼칩니다.
   - 오른쪽 수동 기록: 폰·워치에서 온 기록. 관찰 내용을 한 줄 쓰고 Enter. 분류·발언 후보는 [자세히].
   - 설정 → 화면 → **처음에 보이는 정보**에서 '처음부터 자세히'로 바꿀 수 있습니다.
5. 상단 로고 아래 **모바일 화면**을 누르면 바로 기록 화면이 열립니다(반 → 번호 릴 → 저장). PC에서 저장하면 곧바로 알림 팝업이 떠서 관찰 내용을 채우고, 폰(좁은 터치 화면)에서는 팝업 없이 미반영에 쌓입니다.
6. **생기부 생성**(상단 바): 개별 · 일괄 · 검토 세 탭. [체크한 기록으로 세특 만들어줘] → 분량(`1,452/1,500 B · 약 484자`)과 **반영 n/m** 칩. 검토 탭에서 반영도 체크리스트, 지표 막대, 문장–근거 연결도, 학기 타임라인.
   - 초안은 **도입 → 본문 → 마무리**로 씁니다. 도입은 여러 기록에서 거듭 보인 성향을 행동과 함께 평가하고("…질문하였고, …질문하는 등 … 탐구하는 태도가 돋보이는 학생임"), 본문은 활동 · 세부 행동 · 드러난 역량, 마무리는 역량을 모아 평가합니다.
   - **학생활동 · 역량 · 교사의 평가**가 고루 들어가도록(대략 50 · 25 · 15~20%) 지침이 정해져 있고, '구별하기'를 켜면 세 가지가 형광펜과 비율 막대로 보입니다. 평가의 강도는 도달 정도를 따릅니다.
   - 역량과 평가는 기록에 적힌 행동에서만 이끌어 냅니다. 기록에 없는 활동 · 결과 · 반응은 만들지 않습니다(AI를 켜도 같은 원칙).
   - 초안을 쓰는 동안 초안 칸에 진행 표시(흐르는 줄 · 걸린 시간)가 나옵니다.
   - **분량**은 목표 바이트에 가깝게 맞춥니다. 초안은 목표 구간 안을 겨냥하고, 결과가 목표에서 **±30바이트**(한도의 10%가 더 작으면 그만큼, 글자 단위는 10자) 안이면 다시 묻거나 자르지 않고 그대로 둡니다. 한도보다 길게 둔 경우에는 '확인 필요'에 몇 바이트 넘는지 적힙니다.
     - 기록이 분량보다 많으면: ① 역량 표현을 짧은 이름으로(많이 줄어드는 것부터, 필요한 만큼만) → ② 기록을 골라 뺍니다(교사가 강조한 분류와 다른 기록에 없는 역량을 보여 주는 기록을 남김). 마무리 문장은 끝까지 남기고, 목표가 아주 작을 때만 뺍니다. 뺀 기록은 '확인 필요'에 날짜로 적힙니다. AI 초안은 정확한 바이트 수와 이 순서로 다시 쓰게 하고(최대 2회), 그래도 넘치면 본문 문장을 골라 덜어 냅니다.
     - 기록이 적으면: 억지로 늘리지 않습니다. AI 초안은 아직 쓰지 않은 기록이 있을 때만 한 번 늘려 달라고 하고, 없으면 짧은 이유를 남깁니다.

## 4. 실제 사용 흐름

### 4.1 PC 첫 설정 (약 5분)
1. 학교급(초·중·고) → 카테고리·작성 항목·분량(NEIS 바이트)·문체 지침이 정해집니다.
2. 영역(교과·동아리 등) → 반·명단(엑셀 또는 이름 붙여넣기) → 시간표(칸을 끌어 반 지정) → 진도(시간표로 만든 빈 양식에 단원·제목).
3. 개별 설정 → 성취기준·지침: 성취기준 원문을 붙여넣고 단원에 연결, 교사 지침(문장 길이·강조 카테고리·꼭 넣을/쓰지 말 표현) 입력.

### 4.2 폰 연결
1. PC 설정 → 동기화 → 릴레이 주소 → [동기화 키 생성] → QR.
2. 폰 앱 → 설정 → QR 스캔. 시간표·진도·카테고리가 폰으로 내려갑니다.
3. 홈 화면에 누가 위젯(4×2)을 둡니다.

### 4.3 수업 중 (10초)
- 위젯에서 **번호 → [기록]** (번호 칸은 3명씩, 위아래로 스크롤). 번호를 고르지 않고 [기록]을 누르면 번호 릴이 열립니다. 워치는 **[기록] → 번호 릴 → 저장**. 분류(질문·발표·협동·기타)는 묻지 않고, PC 의 쉬는 시간 기록 팝업에서 정합니다. 음성 메모는 선택.

### 4.4 수업 녹음 (선택, 기본 꺼짐)
1. PC 설정 → 녹음 → 사용 조건 4가지 확인(학교 승인, 사전 고지·동의, 외부 전송 검토, 녹음 표시·즉시 중단) → 켜기.
2. 시작 방식: **1탭**(수업 시작 알림의 [● 녹음 시작]) 또는 **하루 대기**(아침에 [오늘 녹음 대기] 한 번).
   - Android 14 이상은 앱이 스스로 마이크를 켤 수 없어 교사의 1탭이 필요합니다.
3. 공통 설정 → AI 에 Gemini 키를 저장한 뒤 녹음 탭의 [폰으로 키 보내기] (종단간 암호화).
4. 음성은 폰에만 두고 24시간 뒤 지웁니다. Wi-Fi 에서 받아쓰기·화자 구분을 하고 스크립트(글)만 PC 로 보냅니다.

### 4.5 수업 후 (30초)
- 도착 알림 → 2차 보완 팝업에서 메모를 관찰 문장으로 다듬습니다(스크립트 후보 클릭 가능).
- 오늘 페이지 추천함에서 추천 카드를 [학생 지정]·[나중에]·[무시].

### 4.6 학기 말
- 누가기록 → [AI 도달 정도 추정] (선택) → 초안 작성(개별·일괄) → 검토 → 엑셀·클립보드로 NEIS 에 옮김.

## 5. AI 제공자

| 제공자 | 쓰임 | 데이터가 가는 곳 |
| --- | --- | --- |
| Claude | 초안·추천·구별·도달 신호 | Anthropic API |
| Gemini | 위와 같음 + 폰 음성 받아쓰기 | Google Gemini API (유료 등급 키 권장) |
| OpenRouter | 여러 모델 비교 | OpenRouter (데이터 수집 거부 옵션으로 전송) |
| 로컬 LLM | 초안·추천 (외부 전송 없음) | 이 PC 안 (llama-server, 127.0.0.1) |
| 규칙 기반 | AI 를 끈 경우 | 외부 전송 없음 |

- API 키는 Windows 자격 증명 관리자에 둡니다. 백업·내보내기 파일에 넣지 않습니다.
- 초안 요청에는 반·번호·이름이 없습니다. 도달 정도는 숫자가 아니라 표현 방향(서술어 강도·어휘)으로만 전달합니다. 전송 본문은 설정 → AI → [전송 내용 미리보기]에서 확인합니다.
- 로컬 LLM 은 8GB 메모리·GPU 없는 PC 기준 3~4B 4비트 모델(Qwen3 4B, Gemma 3 4B 등 공개 라이선스)을 씁니다. 작은 모델은 **단계형 생성**(문장 슬롯마다 한 문장씩)으로 지시 준수를 높입니다.

## 6. 프롬프트 반영도

초안마다 아래 규칙을 자동 점검하고, 통과한 규칙 ÷ 점검한 규칙을 반영도로 보여 줍니다. AI 로 만든 초안이 95% 미만이면 어긴 문장만 다시 쓰게 합니다(최대 2회).

명사형 종결 · 존칭·감탄 없음 · 주어 생략 · 기재 금지어 · 학생 이름 · 한도 이하 · 목표 구간 · 모든 문장에 근거 · 근거와 내용 일치 · 근거 밖 핵심어 · 도달 정도에 맞는 표현 · 평가 비중 · 카테고리 균형 · 교사 지침(꼭 넣을/쓰지 말 표현, 문장 길이, 강조 카테고리). 자유 문장 지침은 "자동 점검 불가"로 표시합니다.

## 8. 개인정보·보안

- 학생 이름은 PC 에만 있습니다. 폰·워치·서버에는 반·번호만 오갑니다.
- 기기 간 전송은 AES-256-GCM 종단간 암호화이며, 릴레이는 암호문만 24시간 보관합니다.
- 수업 음성은 폰에만 두고 24시간 뒤 지웁니다. 화자 라벨은 학생과 연결하지 않으며 성문을 저장하지 않습니다.
- 도달 정도는 PC 내부 값이며 생기부 문장과 내보내기에 나오지 않습니다.
- 자세한 내용: [개인정보 처리방침](PRIVACY.md), [프로토콜](PROTOCOL.md).

## 9. 문제 해결

| 증상 | 확인 |
| --- | --- |
| 폰이 PC 에 연결되지 않음 | 릴레이 주소(같은 Wi-Fi 면 `http://<PC IP>:8787`), PC 방화벽에서 8787 허용 |
| 녹음 버튼이 없음 | PC 설정 → 녹음에서 사용 조건 확인 후 켰는지, 폰이 설정을 받았는지(폰 설정 → 지금 동기화) |
| 스크립트가 오지 않음 | 폰 녹음 탭의 상태(변환 대기·실패 이유), Gemini 키 전달, Wi-Fi |
| 로컬 LLM 시작 실패 | 모델 내려받기 완료 여부, 메모리 여유(4B 모델 약 3GB) |
| AI 연결 실패 | 설정 → AI → [연결 테스트] 의 오류 문구 |

## 10. 개발·검증

- 테스트: core 단위 테스트, 릴레이 통합 테스트, Kotlin 공통 모듈 테스트(TS↔Kotlin 암호화 교차 검증 포함).
- 에뮬레이터(Android 15)에서 페어링 → 설정 수신 → 마이크 포그라운드 녹음 → 일시정지·중단 → 파일 저장을 확인했습니다.
- 합성 모의 수업 음성: `GEMINI_API_KEY=… node tools/make-demo-lesson.mjs --transcribe` (대본을 음성 합성으로 읽혀 만들고 받아쓰기 결과와 비교).
